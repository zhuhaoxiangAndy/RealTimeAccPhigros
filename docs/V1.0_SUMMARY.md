# RealtimeAcc 开发总结报告 (v0.1 -> v0.5)

## 1. 目标回顾
依据 docs/TECH_REQ.md 开发 Phigros 实时辅助：屏幕/录像捕获 -> 分数区 OCR ->
判定增量分解（P/G/B/M）-> 实时 ACC 与目标联动（判红）。

## 2. 架构
- config.py: 全部可调参数 + TOML 覆盖 (config.example.toml)
- capture.py: 离线视频 (frames_from_video) / 实时屏幕 (live_frames, mss)
- judge.py: 分数 OCR (ocr_score) + 增量分解 (decompose_delta) + 离线判定 (OfflineJudge)
- acc.py: ACC 数学 (TECH_REQ ch.2 公式, 未改动)
- target.py: 目标 ACC (Target.verdict -> is_red 判红)
- main.py: CLI (video / raw / run [--demo])
- reconcile.py: v0.2 对账报告 -> runs/report_*.md

## 3. 判定计数原理 (关键发现)
- 分数显示 7 位, 右上角 x1910:2360 y55:145 (2360x1640 录制)。
- 采样每 12 帧 (0.2s@60fps), OCR 管线: crop -> 2x 立方放大 -> CLAHE(2.0) ->
  threshold(100) -> psm7 纯数字 -> 滑窗提取合法 7 位子串 (容忍左缘竖线粘连)。
- 读到汁分增量 -> 分解为 (P, G): 每音符显示值落在区间
  P:[1227,1365] / G:[798,935] (累计取整漂移), 优先最大 P 解
  (G 占比仅约 5%, 3G 连爆概率极低)。
- 抖动处理: 负增量跳过不重置 (平板期读数 ±600 抖动), 失败增量保留上次锁定值。
- 播放窗口: 显式 [video] start/end, 未指定时倒退锚定 (anchor_window)。

## 5. 与结算页基准的对账 (sample.mp4, Winter cube IN Lv.13)
- 结算页: P=693 G=35 B=1 M=4 N=733  ACC=97.65%  Score=910880
- 判定计数: P=659 G=34 (B+M 无法分开)
- N 兜底: 733 - 659 - 34 = 40 音符未能归因 (约 5.5%)
- 一致率: P 95.1% / G 97.1%
- ACC(判定, N=733): 92.92% vs 结算 97.65%, 偏差 -4.73pp (未达 <0.1pp 目标)

## 6. 已知偏差与根因 (记录在案)
1. 游戏设置关闭了判定花体字 (录像样本), 判定文字 OCR 路线不可行 ->
   无法区分 B/M, 只能合并计数并靠 N 兜底 -> 40 音符归因缺口。
2. 结算明细页为半透明灰字样式, 实时 OCR 不可靠 (深灰底 107 / 亮字 255 双峰
   但字形被面板裁切), 基准值采用分析期读得的结算页静态数值; 代码留
   calib.find_result_page 钩子待改进预处理 (TECH_REQ ch.6 后续工作)。
3. ACC 偏差主要由 #1 的 40 音符缺口造成; 修复路径: 恢复判定文字显示
   (录像设置) 或接入游戏内 ACC 区域直读。

## 7. 使用
见 docs/TECH_REQ.md; 快速路径:
  python main.py video sample.mp4            # 离线计数
  python reconcile.py sample.mp4             # 对账报告 (runs/)
  python main.py run --demo                  # 1x 回放自测
  python main.py run                         # 实时屏幕判定
